# Kit de validación con usuarios

Sesión de validación del prototipo con la Fundación Nueva Luz (Pasto).

- **Duración:** 45 a 60 minutos por participante.
- **Participantes:** 3 a 5. Lo ideal es al menos una persona con ceguera total, una con baja
  visión y una del personal (instructor de orientación y movilidad o acompañante).
- **Objetivo:** verificar que los requisitos responden a necesidades reales, medir la usabilidad
  con SUS y recoger mejoras. Todo esto alimenta los capítulos 4 y 5 del informe.

---

## 1. Antes de la sesión

- [ ] Carta o mensaje enviado a la fundación con fecha y hora confirmadas.
- [ ] Teléfono cargado al 100 %, con la app instalada, el volumen alto y TalkBack probado.
- [ ] Paquete de voz en español sin conexión instalado (ver el manual, sección 3).
- [ ] Cordón o soporte de pecho para el teléfono (puede ser improvisado).
- [ ] Recorrido corto y seguro elegido con el instructor: unos 30 m con 2 o 3 obstáculos
  (personas, una banca, una silla). Si es posible, cerca de la fundación.
- [ ] Copias impresas del consentimiento y de la hoja de registro. El SUS se lee en voz alta.
- [ ] Modo de pruebas listo para CP-05 (opcional): Ajustes → Modo de pruebas.

## 5. Preguntas después de las tareas

1. ¿Qué fue lo más útil de la aplicación?
2. ¿Qué le molestó o le confundió?
3. ¿Las alertas llegaron a tiempo? ¿Eran demasiadas, pocas o las justas?
4. ¿La vibración se sentía bien? ¿Prefiere voz, vibración o ambas?
5. ¿Qué obstáculos de Pasto le preocupan más y la app no avisó?
6. ¿Usaría esta app en su vida diaria? ¿En qué situaciones?

## 6. Cuestionario SUS (System Usability Scale)

Se lee cada frase y la persona responde de 1 (totalmente en desacuerdo) a 5 (totalmente de
acuerdo).

| # | Afirmación | P1 | P2 | P3 | P4 | P5 |
|---|---|---|---|---|---|---|
| 1 | Creo que me gustaría usar esta aplicación con frecuencia. | | | | | |
| 2 | Encontré la aplicación innecesariamente compleja. | | | | | |
| 3 | Pensé que la aplicación era fácil de usar. | | | | | |
| 4 | Creo que necesitaría el apoyo de una persona experta para poder usar esta aplicación. | | | | | |
| 5 | Encontré que las funciones de la aplicación estaban bien integradas. | | | | | |
| 6 | Pensé que había demasiada inconsistencia en la aplicación. | | | | | |
| 7 | Imagino que la mayoría de las personas aprenderían a usar esta aplicación muy rápido. | | | | | |
| 8 | Encontré la aplicación muy difícil de usar. | | | | | |
| 9 | Me sentí muy seguro(a) usando la aplicación. | | | | | |
| 10 | Necesité aprender muchas cosas antes de poder usar esta aplicación. | | | | | |

**Cálculo del puntaje:**
- En las frases impares (1, 3, 5, 7, 9), se resta 1 a la respuesta.
- En las frases pares (2, 4, 6, 8, 10), se resta la respuesta a 5.
- Se suman los diez resultados y la suma se multiplica por 2,5. El puntaje va de 0 a 100.

**Interpretación** (Bangor, Kortum y Miller, 2009):

| Puntaje | Interpretación |
|---|---|
| Menos de 51 | No aceptable |
| 51 a 67 | Marginal |
| 68 | Promedio |
| 68 a 80 | Bueno |
| Más de 80 | Excelente |

La meta del proyecto es **68 o más**.

## 8. Clasificación de los comentarios

No todo comentario obliga a cambiar la app. Cada uno se clasifica y se justifica la decisión:

| Categoría | Criterio | Decisión |
|---|---|---|
| **Crítico** | Pone en riesgo la seguridad o impide usar la app | Se corrige antes de la entrega |
| **Mejora pequeña** | Mejora clara y de bajo esfuerzo (un texto, un volumen, un patrón de vibración) | Se corrige si el tiempo lo permite |
| **Trabajo futuro** | Valiosa, pero fuera del alcance o del tiempo (nuevas clases de objetos, navegación paso a paso) | Se documenta en el capítulo 5 |
| **Ya cubierto** | La función ya existe pero no se descubrió | Se mejora el manual o la ayuda por voz |

## 9. Cómo reportarlo en el informe

- Tabla de tareas: porcentaje de éxito por tarea y tiempos.
- SUS: puntaje de cada participante, promedio y su interpretación.
- Tabla de clasificación de comentarios con su decisión.
- Limitaciones: tamaño de la muestra (3 a 5 personas), sesión única y recorrido controlado.
  Con 5 usuarios se detecta la mayoría de los problemas de usabilidad (Nielsen y Landauer, 1993),
  pero los resultados no se generalizan estadísticamente.
